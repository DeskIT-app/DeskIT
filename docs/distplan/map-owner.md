## Purpose

This subsystem exists because the owner develops the app on the same machine he dictates on, with Claude Code. It has five families:

1. **Problem reports** (`problems.py`, `problem_card.py`, the Problems place in `dashboard.py`, the report key in `main.py`): one typed line, plus everything the app can collect at that moment — a full multi-monitor screenshot, a copy of the last recording and its sidecar, the raw and final transcript, a settings snapshot and the git branch. Stored locally in `problems.json` + `problems\`.
2. **The Saturday Claude routine** (`weekly_review.ps1`, `.claude/commands/weekly-reports.md`, `questions.py`): a Windows scheduled task runs the local `claude.exe -p /weekly-reports` with `bypassPermissions`; the command reads the reports and their evidence (it opens the screenshots with the Read tool), writes three Markdown documents, may build and commit code onto `main`, marks reports "fixed?" and asks the owner multiple-choice questions.
3. **Push / Undo / Restart** (`dashboard.py` 838-1150, `versions.py`): buttons on the Problems place that `git fetch/push origin main`, `git reset --keep origin/main`, and restart the app; `versions.py` stamps the git branch on every report.
4. **The nightly test run** (`nightly.py`, `nightly_tests.ps1`, `install_nightly_task.ps1`, `tests_quiet.py`): a second scheduled task at 02:55 that puts a Tk card on the desktop, waits five minutes, runs the whole suite including sixteen tests that take the real mouse and screen, and files a problem report on failure.
5. **The notify door and keep-awake** (`notify.py`, `notify_hook.py`, `notify_watch.py`, `notify_card.py`, `awake.py`): a `POST /notify` route on the phone server that Claude Code's Stop/Notification hooks call; a watcher that copies the Windows notification database to read the Claude desktop app's toasts; cards that dismiss themselves when the owner walks into the Claude session; and an engine that holds the machine awake and blanks the screens so he can drive it from his phone.

Families 2, 3, 4 are owner-only by construction. Family 1 is the one feature a normal user wants (as "Report a problem"). Family 5 splits: the keep-awake and the generic notification door are plausibly user features; the Claude-desktop plumbing is owner-only.

## What breaks on a fresh machine

- **The weekly routine does nothing, silently**: `claude.exe` not found → "FATAL" line in `run.log`, exit 0 (`weekly_review.ps1:168-171`); no scheduled task exists unless registered by hand; no owner login → "Not logged in" card (393-395). Its documents quote whichever `problems.json` it finds.
- **The nightly task is not registered** (`install_nightly_task.ps1` is manual, AGENTS.md 1041-1042); if a user ran it, it would wake the PC at 02:55 and take the mouse; `KNOWN_FLAKES` names a test that only flakes here (`nightly.py:168-172`); `tests.py`/`tests_quiet.py` must be present.
- **The hook is dead until installed**, and dies again when the folder moves (absolute paths in `settings.json`, `notify_hook.py:426-427`); it also fails silently when `[server] enabled` is false (the code default, `config.py:1117`) or `server_token.txt` does not exist yet (`notify_hook.py:531-533`).
- **`notify_watch` runs anyway**: with the shipped `watch = "cowork"` (`config.toml:1130`) it stats the notification DB four times a second and copies ~2 MB to `%TEMP%` on every toast from any app, even with no Claude installed (`notify_watch.py:395-424`).
- **Arrival watch warns on every column** without the Claude desktop app (`notify.py:1355-1358`).
- **`versions.current_branch()` returns "(unknown)"** without git (`versions.py:63-66`); `env["branch"]` becomes meaningless; the Problems card's git block shows nothing (`dashboard.py:984-987`) and Push/Undo, if git exists but there is no `origin`, answer "GitHub could not be reached" (`_UNREACHABLE`, 957-959).
- **Cards may open off-screen**: `[notify] x=2188 y=1373` and `[problems] x=1066 y=511` are this desktop's coordinates and are deliberately unvalidated (`config.py:884-893`).
- **The awake probe's verdict mentions Claude** (`awake.py:421-432`) and shells out to PowerShell/WMI (338-380) on every screens-off; harmless but odd on a user's PC.
- **Everything writes into the code folder** (`APP_DIR`), which under `Program Files` is not writable; `problems.py:596`, `notify.py:281`, `awake.py:1228`, `nightly.py:213-219`, `dashboard.py:890` all `mkdir`/write there.
- **`config.toml` defaults drift**: `ServerConfig.enabled=False` in code vs `true` in the file; `dismiss_on_arrival` exists in code (`config.py:809`) but not in the file; a config regenerated from code defaults changes behaviour.
- **Docs disagree**: README 3251-3265 says the routine "fixes nothing — no code, no config, no commit" and runs "Saturday 08:00"; `weekly-reports.md` (post 2026-09-12) builds and commits; the task fires at 04:00. A user guide must not inherit either text.
- **`tests.py` asserts on developer files and README strings** (`tests.py:25281` `--install-hook` in README; `:28490-28510` contents of `nightly_tests.ps1`/`install_nightly_task.ps1`), so removing the dev files breaks the suite unless it is split.

## Distribution risks

1. **The report bundle is the most sensitive object in the app**: a full multi-monitor screenshot (`main.py:3770`), a copy of the user's voice (`problems.py:375-397`), raw+final transcript and per-word confidences (`problems.py:151-152, 331-353`), and a settings snapshot. Today it never leaves the machine except through the owner's own routine, which uploads the screenshot and text to Anthropic under HIS account (`weekly-reports.md:352-355`). If a backend ingests reports without per-attachment consent, the owner becomes the custodian of other people's screens and voices.
2. **`remove()` leaves the wav and jpg on disk** (`problems.py:869-874`; dashboard says so, 4568-4570). A user who "deletes" a report has not deleted the evidence.
3. **`notify.json` keeps excerpts of the user's Claude conversations** (`notify_hook.py:351-352`; `notify.py:289-314`) in the app folder; `notify.log` grows without a cap.
4. **`notify_watch` copies the whole OS notification database (all apps) to `%TEMP%`** with the shipped default on (`notify_watch.py:147, 405-424`; `config.toml:1130`).
5. **Owner-only machinery would ship as live buttons**: Push/Undo (`dashboard.py:1010-1114`), `Open problems.md`, Stop-tests, the `-Answered` spawn of `weekly_review.ps1` (5126-5190). With git present they act on whatever `origin` the user's folder has.
6. **`bypassPermissions` + scheduled code changes** (`weekly_review.ps1:123, 269-276`) and a nightly job that takes the mouse and wakes the PC (`install_nightly_task.ps1:106`) must never reach a user; both are trivially registered by a curious user because the scripts sit in the folder.
7. **Owner identity baked in**: "Yoav" (`nightly.py:487`), Hebrew failure copy (`weekly_review.ps1:394-401`), typed `C:\Users\shimr\…` paths (`weekly_review.ps1:42, 103`; `nightly_tests.ps1:40`).
8. **`hold = true` keeps every user's PC awake for as long as the app runs** (`config.toml:1042`; `main.py:1985-1989`), and `pin_timeouts` edits the power plan with a crash-recovery path that only runs at the next start (`awake.py:1305-1336`).
9. **Data in the code folder, protected only by `.gitignore`**: an installer under `Program Files` cannot write there and an unpacked zip in `Downloads` mixes code with `problems\*.wav`.
10. **One bearer token for the phone page (in the URL fragment) and the local hook**, stored in plain text beside the code (`server.py:69, 653`; `notify_hook.py:54`).
11. **Config/code default drift** (`[server] enabled`, `dismiss_on_arrival`) and **doc drift** (README vs the routine) will leak into a user guide generated from the comments.
12. **The test suite is entangled with the dev files** (`tests.py:25281, 28490-28510`), so the product build cannot simply drop them without a test split.

## Recommendations for the plan

1. **Split the tree into `product/` and `dev/` (or a package manifest)**. Exclude from the installer: `weekly_review.ps1`, `.claude/`, `questions.py`, `nightly.py`, `nightly_tests.ps1`, `install_nightly_task.ps1`, `tests.py`, `tests_quiet.py`, `VISUAL_QA_PLAN.md`, `PARALLEL_FEATURES_PLAN.md`, `AGENTS.md`. In `dashboard.py`, delete the git block (838-1114), `_wake_review` (5126-5190), `_nightly_running/_stop_tests` (8019-8052), the `Open problems.md` button (4058-4060) and the "what is on this computer and not on GitHub" card; keep `restart_app()`.
2. **Introduce a data directory**: `paths.DATA_DIR = %LOCALAPPDATA%\DeskIT` (override `DESKIT_HOME`), with `problems.json`, `problems\`, `notify.json/.log`, `awake.log/awake_state.json`, `server_token.txt`, `config.toml` and the transient temp copies under it. The engines already take an `app_dir`/`store_path` (`notify.Engine` 832-852, `awake.Engine` 960-971, `problems.record(app_dir…)` 899) — the change is at the call sites in `main.py:364, 487, 687` and `notify_hook.py:54, 370`.
3. **Replace `versions.py` with `version.py`** reading a VERSION file written by the build; `problems.env()` (274-302) reports `version`, `os_build`, `backend`, `local_model`, `gpu` (bool), and drops `branch` and `python`.
4. **"Report a problem" v2 on the existing card** (`problem_card.py` is already headless-testable): keep one line + kind chips; add three attachment toggles with what they cost — Screenshot (default on, preview stays; capture the monitor under the mouse by default instead of `all_screens=True`, `main.py:3770`), Recording (default OFF), Transcript text (default on for kind=wrong); add ONE consent checkbox "Send to the developer" (default off = stays on this PC). Store locally exactly as today; queue ticked reports in `problems\outbox\` and upload only the ticked parts through the user's own Supabase session (RLS per user, a Storage bucket per user, a whitelisted column set: `text, kind, where, version, env-whitelist, attachments`). Show the byte size before sending (a report with audio is 0.5–1.6 MB, a screenshot ~100 KB).
5. **Make delete mean delete for users**: `remove()` gains a `purge=True` path that unlinks the pinned wav/json/jpg when no other report references them (today it never does, 869-874); keep the two-press confirmation (`dashboard.py:4545-4575`).
6. **Map the routine's "fixed?" mark onto the backend**: a `developer_status` column (`replied`, `fixed_in <version>`) that the app syncs into `problems.json` as `MAYBE {by:"developer", note}` (`problems.py:105-111, 806-857`); the user's Fixed/Reopen press (`resolve()`, 771-804) writes back. No new UI is needed — the row already draws the mark in a non-green colour.
7. **Keep the Saturday routine owner-side** and point it at exported backend reports (a `problems/inbox/<user-id>/` folder synced from Supabase) instead of the local store; this dissolves the AGENTS.md objection (455-471) that a cloud routine cannot see `problems.json`. The command must be told which fields are consented; audio is never fetched unless ticked.
8. **Notify door**: ship `[notify] enabled = false` and `watch = "off"`; add a Settings button "Connect Claude Code" that runs `notify_hook.install_hook()` with the installed pythonw path (`notify_hook.py:420-451`) and shows the two hook entries it wrote; make `notify_watch.Store._copy` a no-op unless a `Claude_*` package exists; write its copy under `DATA_DIR\tmp`; cap `notify.log` like `awake.log` should be (rotate at 512 KB the way `nightly.py:232-237` does).
9. **Awake**: ship `hold = false` and ask at first run ("Keep this PC awake while DeskIT runs? You can change this in Settings."); `vitals_minutes = 0`; `pin_timeouts` under Advanced with the sentence "changes the Windows power plan; restored on exit"; drop the `claude.exe` probe (`awake.py:421-432`) or rename it "remote-control app".
10. **Move window positions out of `config.toml`** (`[notify] x/y`, `[problems] x/y/card_x/card_y`) into `DATA_DIR\state.json`, and clamp to the current virtual screen at load (`config.py:884-893` explains why they are unvalidated; a state file with a clamp keeps that reasoning and stops the Settings page from showing coordinates).
11. **Fix the default drift before generating docs**: make `ServerConfig.enabled` agree with the shipped file (or make the shipped file the source of truth for the generated Settings page), add `dismiss_on_arrival` to the file or delete it from the code.
12. **Split `tests.py`**: product tests vs owner-ops tests (`tests.py:25281`, `28490-28510` and everything importing `nightly`, `questions`, `weekly_review.ps1`), so the product build's CI passes without `dev/`.
13. **The "keys never reach the owner" proof, this subsystem's part**: keep `problems.env()` a whitelist (it already is, 286-299); add a test that serialises a full report with a populated `.env` and asserts none of the key values appear in the JSON, the digest, or the outbox payload; publish the uploader module and the Supabase column list; the backend must reject any column outside the whitelist.
14. **User guide scope for this subsystem**: Report a problem (what is attached, what is sent and when, how to see and delete it), Notifications from other programs (optional, how to connect Claude Code), Keep awake / screens off. Nothing about branches, Push/Undo, nightly tests or the Saturday routine.
